# Weekly Project Report: 2026-06-15 to 2026-06-21

## Summary

This week focused on establishing the Unity-side foundation for Biosphere Balance Lab. The main progress was the initial dependency injection architecture, ECS initialization flow, script generation tooling, naming/code standards, and project documentation structure.

The project moved from a basic Unity setup toward a clearer simulation architecture: managed services can now be registered and resolved, ECS systems can be bootstrapped through the project container, creature metadata can be generated, and creature entities can be initialized from that metadata.

## Overall Progress

This week I focused on building the first real foundation for Biosphere Balance Lab. The project started as an early Unity setup, and the main work was to turn it into a more structured simulation codebase with clearer architecture, stronger conventions, and an initial ECS-driven initialization flow.

On the architecture side, I introduced a lightweight dependency injection system designed specifically for this project. The goal was not to add a large framework, but to create a small, explainable layer for registering managed services, switching implementations, resolving configuration, and connecting Unity scene or asset references to runtime systems. This gives the project a cleaner way to handle future scenario presets, test doubles, prefab lookup, bridge services, and other managed dependencies without scattering global lookups through the codebase.

I also connected that architecture to Unity ECS. I added the first system registration flow through `GameBootstrapper`, created infrastructure for associating containers with ECS worlds, and made it possible for managed ECS systems to resolve project services through a shared container. This is an important step because the project needs to keep simulation data in ECS components while still allowing higher-level Unity services and configuration to be managed cleanly.

For the simulation itself, I started the creature initialization model. I added basic ECS components such as IDs, timestamps, metadata references, health, energy, diet, lifespan, and death tags. I then added an initial metadata system that creates creature metadata entities and an initialization system that creates plant entities from that metadata. This does not yet represent the full biosphere simulation, but it establishes the pattern for how organisms can be generated, identified, tracked, and connected to future ecosystem logic.

I spent part of the week improving the Unity development workflow as well. I added an ECS script template generator inside the Unity editor so new components, tag components, structs, `SystemBase` systems, and `ISystem` systems can be created with consistent namespaces and structure. This reduces repetitive setup work and helps future ECS code follow the same style from the beginning.

Another major part of the work was project organization and readability. I applied the `BioSphereLab` namespace structure, cleaned up example code organization, improved the Unity dependency injection README, added an editor helper for viewing that README, renamed the main Unity scene, and added early asset-storage support through `StorageInjection`. These changes make the Unity side easier to navigate and easier to explain as a portfolio project.

Finally, I built out the documentation base around the code. I added or updated the roadmap, architecture notes, decision log, code standards, backlog, and AI-assistance guidance. These documents define the project direction, explain key technical choices, record why the dependency injection approach was chosen, and establish coding conventions for future C# and Unity work. By the end of the week, the project had both a stronger technical foundation and a clearer written record of how the project should continue.

## Implemented Work

### Unity dependency injection foundation

- Added an in-repository dependency injection layer for Unity runtime code.
- Added interfaces and infrastructure for registering, resolving, and switching managed services.
- Added ECS integration so managed ECS systems can resolve dependencies through `InjectedSystemBase`.
- Added world-to-container registration through `EcsInjectionRegistry` and related extension methods.
- Added example spawn policies to demonstrate switchable behavior, including balanced and stress-test biosphere policies.
- Documented the DI approach in `docs/decision-log.md` and `docs/architecture.md`.

### Unity namespace and project readability cleanup

- Applied the `BioSphereLab` namespace structure across Unity-side scripts.
- Reorganized dependency injection example code into clearer namespaces and folders.
- Added a more readable Unity-side dependency injection README under `unity/Assets/Scripts/DependencyInjection/Examples/README.md`.
- Added an editor helper for viewing the dependency injection README inside Unity.

### ECS script template generator

- Added a Unity editor tool at `Tools/BioSphereLab/Scripting/ECS Template Generator`.
- Added project menu presets for generating:
  - ECS component scripts
  - Tag components
  - Plain structs
  - `SystemBase` systems
  - `ISystem` systems
- Added validation for C# identifiers, namespaces, and Unity `Assets/` target paths.
- Added script previews and overwrite protection to make generated ECS code safer to create.

### Initial simulation data and creature initialization

  - `TimeStamp`
  - `MetaDataRef`
  - `Health`
  - `Energy`
  - `Diet`
  - `LifeSpan`
  - `DeadTag`
- Added `CreatureSpawnConfig` and constants for initial creature counts.
- Added `CreatureMetadataSystem` to create metadata entities with IDs, timestamps, and lifespan data.
- Updated `CreatureInitSystem` to create plant entities from metadata and link them through `MetaDataRef`.
- Registered initialization systems through `GameBootstrapper`.

### Unity asset and scene setup

- Added and updated Unity project settings related to ECS and scene templates.
